Glasses UI — containers

bridge.createStartUpPageContainer(cfg) → 0|1|2|3
One-shot. Must be called exactly once at boot. Max 4 containers, exactly one has isEventCapture:1. Coord origin is top-left, X right, Y down.
used in: src/Main.ts → buildHomePage()
bridge.rebuildPageContainer(cfg) → boolean
Every screen after the first uses this — home, philosopher select, mindstate, quote view, speak flow.
used in: src/events.ts (all navigation)
bridge.updateImageRawData({ containerID, containerName, imageData })
Pushes the grayscale PNG bytes for an image container. Must be serialized — no concurrent pushes. soPHICON queues awaits.
used in: src/image-utils.ts → pushImg()
bridge.textContainerUpgrade({ containerID, content, contentOffset, contentLength })
Swap text in a text container without a full rebuild. Not currently used — soPHICON rebuilds the page on each quote; could speed up auto-rotate.
potential optimization for quote rotation
bridge.shutDownPageContainer(exitMode?)
0 exits immediately, 1 shows the foreground interaction layer. Not currently wired — no explicit exit path.
unused

Sprite pipeline — how pixel-art philosophers hit the glass

23 emotions × 17 philosophers = 391 sprites. Every sprite goes through a custom grayscale PNG encoder before the SDK will accept it — the glasses' framebuffer can't render arbitrary PNG formats.

1
Source PNGs public/sprites/<phil_id>/<phil_id>-<emotion>.png
e.g. socrates/socrates-conviction.png. Emotions used: neutral · contemplation · conviction · wonder · serenity · defiance · sorrow · urgency · joy · compassion · awe · acceptance · authority · devotion · doubt · grief · honor · liberation · peace · rage · resolve · teaching · transcendence.
folder
↓
2
Fetch + canvas fit fetchAsGrayscalePng() in src/image-utils.ts
Scales into target box with letterbox, fills bg black, reads pixels, then grayscale: g = 0.299·R + 0.587·G + 0.114·B.
edit
↓
3
Encode encodeGrayscalePng() in src/pngEncoder.ts
Custom encoder: 8-bit grayscale, no filter, uncompressed DEFLATE blocks, Adler32 + CRC32 checksums. ~120 lines, no deps. The G2 firmware expects this exact shape.
edit
↓
4
Push pushSpriteSingle / pushSpritesSplit
Split: 200×200 sprite → two 200×100 halves for the big portrait (containers 3 top + 11/12 bottom). Single: 100×100 for the speak conversation face.
same file
↓
5
On glass bridge.updateImageRawData({ containerID, imageData })
Bytes become an ImageContainerProperty. Rule: never concurrent — always await the previous push. Memory on-glass is tight.
runtime

To add or swap sprites

# 1. Drop PNGs into public/sprites/<phil_id>/<phil_id>-<emotion>.png
#    — any source size works; encoder downscales to target (100x100 or 200x200)
#    — prefer simple, high-contrast pixel art (grayscale collapse is lossy)
# 2. If the emotion is new, add it to:
#    src/speak.ts → emotionToSprite() valid[] array
#    sophicon-api/api/speak.js system prompt emotion list
# 3. Wire a quote to it by setting the `sprite` field in the source JSON,
#    then regenerate constants.ts (see Quote pipeline above).

API keys & the Speak pipeline

The SDK does not store keys. All keys live server-side on Vercel as env vars — they must never enter the web bundle.

POST https://sophicon-api.vercel.app/api/speak
Calls GPT-4o with the persona + history. Reads process.env.OPENAI_API_KEY. System prompt builds from public/personas.json. Returns { text, emotion } (emotion parsed from [EMOTION:tag] line).
file: sophicon-api/api/speak.js
POST https://sophicon-api.vercel.app/api/transcribe
Takes base64 PCM from the glasses mic, wraps it in a WAV header (16 kHz, 16-bit, mono), forwards to gpt-4o-transcribe. Optional language (ISO 639-1).
file: sophicon-api/api/transcribe.js · uncommitted diff: language param added

Rotating / adding keys

# On Vercel (sophicon-api project):
vercel env add OPENAI_API_KEY production
vercel --prod                  # redeploy so the function picks it up

# Do NOT put the key in .env bundled with the Vite app — everything in src/ ships to the client.

Backend & accounts — Supabase roadmap

Plan for moving soPHICON from on-device-only to a multi-device platform with auth, tier-gated entitlements, and journal sync. Living doc — update phases as they ship.

Enki — the foundational philosopher

Enki is the one philosopher every user meets first. Sumerian god of wisdom, water, knowledge, and craft — predates Greek philosophy by millennia, single syllable, distinctive. He's the user's personal companion; the other 17 historical philosophers are figures Enki can introduce them to. Enki's capacity scales with tier (same character, deepening relationship), which is the primary tier mechanic — not just "more philosophers unlocked".

Free Enki — Seeker tier
Friendly, helpful base persona. Soft cap on context depth. Reads only the surface fields of UserProfile (name, language, life role). Conversation history capped at last 10 turns sent to GPT. No cross-philosopher awareness.
entry experience · "where do I start?" answered
Deep Enki — Examined tier
Full UserProfile injected as ABOUT THIS PERSON. Last 14 days of cross-philosopher journal as quiet awareness. User's guidelines are followed verbatim. History extended to last 40 turns. Personalized within the user's frame.
primary value of paid tier · the relationship deepens
Uncapped Enki — Sage tier
Persistent semantic memory across all conversations (RAG over full journal, not just 14 days). Cross-philosopher narrative awareness — Enki references your conversations with Marcus, Buddha, Seneca by name when it serves you. User can shape Enki's tone/voice/values via long-term guidelines Enki actively negotiates.
power tier · Enki as a true second mind
Implementation hooks
Enki lives in personas.json with philId: "enki". Server-side /api/speak reads userProfile.tier and adjusts Enki's system prompt — depth caps, cross-context inclusion, guideline weight. Sprite set: needs commission for 23 emotion variations matching the canonical list. Visual: Sumerian/Mesopotamian aesthetic, GBA-era pixel art.

Tier structure

Seeker — free
Quotes-on-glass full corpus stays free. Speak with Free Enki only. 5 conversations/day. 1 active habit. 30-day journal retention. No cross-device sync.
entry tier · friction-to-first-value preserved
Examined — monthly
From Socrates: "the unexamined life is not worth living". Speak with all 17 historical philosophers. Enki upgrades to Deep mode. Unlimited Speak. Weekly action plan. 5 active habits. Full journal sync across iOS / Android / G2. 1-year retention.
primary paid tier · target ~$8/mo
Sage — annual or lifetime
Adds custom user-added philosophers. Enki upgrades to Uncapped mode. Mini-philosopher fine-tuned voice models when they ship. Priority transcription. Unlimited journal retention.
power tier · target ~$60/yr or lifetime
Naming alternatives considered
Pupil / Companion / Disciple (relational) · Logos / Phronēsis / Sophia (pure Greek, on-brand but intimidating). Locked in Seeker / Examined / Sage for accessibility + aspirational positioning. Foundational philosopher named Enki on 2026-04-27.

Auth happens on the companion phone app (G2 has no keyboard). Session token gets written to bridge.localStorage as auth_token and the glasses code reads it on every backend call. Phone app + glasses share the same backend account because they share the same token.

Schema (run once in Supabase SQL editor)

-- profiles (1:1 with auth.users)
create table profiles (
  user_id uuid primary key references auth.users(id) on delete cascade,
  name text, language text default 'en', pronouns text,
  life_role text, current_focus text,
  challenges jsonb default '[]', values jsonb default '[]',
  preferences jsonb default '{}', guidelines jsonb default '[]',
  tier text not null default 'seeker',     -- seeker | examined | sage
  tier_until timestamptz,
  stripe_customer_id text,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create table subscriptions (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  tier text not null,
  status text not null,                    -- active | past_due | canceled | trialing
  stripe_sub_id text unique,
  current_period_start timestamptz,
  current_period_end timestamptz,
  created_at timestamptz default now()
);

create table journal_sessions (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  date date not null,
  phil_id text not null, phil_name text not null, tradition text,
  start_ts timestamptz not null, end_ts timestamptz not null,
  exchanges jsonb not null,
  cross_context_used text, device_id text,
  created_at timestamptz default now()
);
create index on journal_sessions(user_id, date desc);
create index on journal_sessions(user_id, phil_id);

create table action_items (
  id text primary key,                     -- <session_id>-<idx>
  user_id uuid not null references auth.users(id) on delete cascade,
  session_id text, phil_name text, tradition text,
  date date not null,
  title text not null, detail text, source text, theme text,
  done boolean default false, done_at timestamptz,
  created_at timestamptz default now()
);
create index on action_items(user_id, date desc);

create table habits (
  id text primary key,                     -- matches favorited action.id
  user_id uuid not null references auth.users(id) on delete cascade,
  title text not null, detail text, source text,
  phil_name text, phil_id text, tradition text,
  themes jsonb default '[]', tag_hints jsonb default '[]',
  quote jsonb,
  active boolean default true,
  streak int default 0, best_streak int default 0,
  last_done_date date, last_check_in_date date,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create table habit_check_ins (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  habit_id text not null references habits(id) on delete cascade,
  for_date date not null,                  -- the day being reviewed
  status text not null,                    -- done | missed | skipped
  ts timestamptz not null,
  unique(habit_id, for_date)
);

create table weekly_overviews (
  user_id uuid not null references auth.users(id) on delete cascade,
  week_key text not null,                  -- YYYY-WW
  problems jsonb not null,
  generated_at timestamptz default now(),
  primary key(user_id, week_key)
);

-- Row-level security: every table is users-can-only-see-their-own
alter table profiles            enable row level security;
alter table journal_sessions    enable row level security;
alter table action_items        enable row level security;
alter table habits              enable row level security;
alter table habit_check_ins     enable row level security;
alter table weekly_overviews    enable row level security;

create policy "own profile"  on profiles            using (user_id = auth.uid());
create policy "own journal"  on journal_sessions    using (user_id = auth.uid());
create policy "own actions"  on action_items        using (user_id = auth.uid());

create policy "own checkins" on habit_check_ins     using (user_id = auth.uid());
create policy "own weekly"   on weekly_overviews    using (user_id = auth.uid());

Sync strategy (local-first, last-write-wins)

On app open
Pull last 30 days of journal + all habits + active week's overview + profile. Hydrate local stores. Cloud wins on conflict.
single round trip · roughly < 100 KB for typical user
On every write
UI updates instantly from local state. Background fire-and-forget upsert to /api/sync/push. Failed writes queue locally and drain on reconnect.
checkpointSession · favoriteAsHabit · setActionDone · saveProfile
Conflict resolution
Journal sessions are append-only with stable UUIDs — no real conflict. Profile + habits use last-write-wins by updated_at.
acceptable for personal-journal app · rarely two simultaneous devices
Offline mode
Existing bridge.localStorage is the local cache. App functions fully offline; queued writes drain on reconnect.
no extra work — local-first is already how everything is wired

Subscription management UI (cancel, change plan, restore). Retention enforcement (delete > 30 days for Seekers). Conflict-resolution edge cases. Receipt validation for App Store / Play.

UX decision: Speak is gated, quotes-on-glass stays free

The original product — philosophy quotes auto-rotating on the G2 — should remain available without an account. That's the friction-to-first-value hook. Account creation is only required when a user opens Speak (the philosopher conversation feature). All Seeker-tier features are advertised; locked features show a "Examined or Sage required" hint with a one-tap upgrade flow.

When ready to start Phase 1

Create the Supabase project, run the schema SQL above, enable Apple + Google OAuth providers. Then we scaffold the Sign-in screen, token storage, /api/me, and auth-header injection across the existing endpoints.
